The Mission

Transform documents into actionable knowledge

Users upload a heterogeneous corpus — PDFs, markdown, source code — and Corpus Forge lets them chat with it, study it, and review it, with answers grounded in their own files instead of hallucinated by the model.

  • Chat with retrieval-grounded answers
  • Auto-generated quizzes and flashcards
  • Structured code review for source files
  • Persistent corpus and generated artifacts
  • Live token & request observability

Ingestion Deep-Dive

From raw upload to searchable vectors

📥
Upload
10 MB cap · streamed in 1 MB chunks · type whitelist · sanitized filename
📝
Extract
PyMuPDF for PDFs · UTF-8 read for text/code · scanned-image PDFs rejected
✂️
Chunk
1000 chars · 200 overlap so sentences don't get cut at boundaries
🔢
Embed
all-MiniLM-L6-v2 → 384-dim vector per chunk
💾
Store
ChromaDB with {filename, type} metadata · re-upload replaces old chunks
Why this matters: chunk size, overlap, and embedding model are the three levers that make or break retrieval quality. We tuned each one deliberately.

Engineering Challenge D

Reliability & Security · auditing our own code

We ran a brutal AI security audit on day 1

  • Path traversal blocked via sanitize_filename
  • DoS via huge uploads → 10 MB streaming cap
  • Temp file leaks → guaranteed cleanup in finally
  • CORS wildcard → tightened to localhost by default
  • Generic error responses → no stack traces leaked

Failure scenarios handled

  • Empty / scanned-image PDFs → friendly 400
  • Duplicate uploads → replace old chunks, no doubles
  • Unsupported file type → rejected at upload
  • Missing context for chat → 404, no hallucination
  • LLM crash → caught, generic 500, secrets never leak

When the AI was wrong

It's not magic — it needs review

Filesystem confusion

AI assumed log files were in records/ after we moved them back to root. Wrote to the wrong directory.

Fix: explicitly stated current paths in the prompt.
Wrong framework

Asked for an artifact endpoint — first response used Flask syntax instead of our FastAPI stack.

Fix: re-prompted with stack reminder; second pass was correct.
Over-eager security

Audit suggested rate-limiting, prompt-injection sanitizing, full RBAC. Most weren't worth the scope.

Fix: filtered findings — fixed real risks, documented the rest.
Duplicate journal entries

The hook logger sometimes wrote the same prompt twice — visible mess in the journal.

Fix: traced root cause to hook config, not code.

Failures & Iterations

What we got wrong the first time

F1
Monolithic main.py

Started as 300+ lines doing everything. Refactored into the app/ package mid-project.

F2
CORS wide open

Started with allow_origins=["*"]. Tightened to localhost after the security review.

F3
No upload limits

A single 5 GB PDF could have crashed the server. Added 10 MB streaming cap.

F4
Token cap by characters, not tokens

24k char ceiling is a heuristic. Honest limitation — a real tokenizer would be tighter.

Lessons Learned

What we'll take with us

🧩

RAG is more about plumbing than magic

Chunk size, overlap, and embedding choice matter way more than the LLM you pick.

📐

Structured outputs change everything

JSON-mode + a schema in the prompt = reliable artifacts the frontend can actually use.

🤝

AI is a tutor, not a shortcut

"Explain this first" produced better outcomes than "write this for me."

🛡️

Audit early, not at the end

Security findings on day 1 became built-in defaults instead of last-minute patches.

📦

Small prompts beat big ones

Six incremental prompts shipped a working frontend. One mega-prompt would not have.

🔍

Trust, but verify

Every AI suggestion got reviewed. Several were good, some were wrong, none merged blindly.
